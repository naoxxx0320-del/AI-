# かんたん運用マニュアル — サイトの公開とマージのしかた

**すみだAIきょうしつ 公式サイトの運用手順書**（保存版）

このマニュアルは、専門知識がない方でも読めるように書いています。
むずかしい言葉には、最初に「たとえ」をつけて説明します。

---

## 0. まず、ことばの意味（1分でわかる用語集）

| ことば | 意味（たとえで説明） |
|--------|--------------------|
| **GitHub（ギットハブ）** | サイトの原稿をぜんぶ預けている「倉庫サービス」。 |
| **リポジトリ** | 倉庫の中の「うちのサイト専用の棚」。うちの棚の名前は `AI-`。 |
| **main（メイン）** | 棚の中の「**本棚（完成品の置き場）**」。ここに置いたものだけがサイトとして公開されます。 |
| **ブランチ** | 「**下書き用の机**」。本棚を汚さずに、机の上で自由に作業できます。 |
| **プルリクエスト（PR）** | 「この下書きを本棚に移していいですか？」という**申請書**。 |
| **マージ** | 申請をOKして、**下書きを本棚（main）に移すこと**。この瞬間に公開が始まります。 |
| **デプロイ** | 本棚の内容を、インターネット上のサイトに**反映する作業**。うちは自動で動きます。 |

### ひとことで言うと

> **下書き（ブランチ）→ 申請（プルリクエスト）→ 本棚に移す（マージ）→ 自動で公開（デプロイ）**

あなたがやるのは「**マージ（本棚に移すのをOKする）**」だけ。あとは全部自動です。

## 2.【いちばん使う】マージのしかた（下書きを公開する）

Claude（AI）が変更を作ると、「下書きができました。マージしてください」と言われます。
そのときは、この手順です。**スマホでもパソコンでも同じ**です。

1. **https://github.com/naoxxx0320-del/AI-** を開く
2. 黄色い帯で「**Compare & pull request**」というボタンが出ていたら、それを押す
   - 出ていない場合：上の「**Pull requests**」タブ →「**New pull request**」→
     上の欄が「base: **main**」、下の欄が「compare: **claude/…**」になっているのを確認 →「**Create pull request**」
3. 緑の「**Create pull request**」を押す（申請書の提出）
4. 次の画面で緑の「**Merge pull request**」を押す（申請をOK）
5. 「**Confirm merge**」を押す（最終確認）

✅ これで完了。**1〜2分待つと、サイトに自動で反映**されます。

> 💡 コツ：ボタンは基本「**緑色のボタンを順番に押していく**」だけです。

---

## 3. ちゃんと公開されたか確認する方法

1. **https://github.com/naoxxx0320-del/AI-/actions** を開く
2. いちばん上の行を見る：
   - 🟡 **黄色い丸** … いま公開作業中。1〜2分待つ
   - ✅ **緑のチェック** … 公開成功！
   - ❌ **赤いバツ** … 失敗。あわてなくて大丈夫（下の「困ったとき」へ）
3. 緑になったら **https://naoxxx0320-del.github.io/AI-/** を開いて確認

> 💡 サイトが古いままに見えるときは、ページを**下に引っぱって更新**（スマホ）またはページの再読み込み（パソコン）をしてください。少し時間がかかることもあります。

## 4.【最初の1回だけ】サイト公開の初期設定（設定済みの記録）

以下は**もう設定済み**です。新しいサイトを別に作るときの参考として残します。

1. **リポジトリをPublic（公開）にする**
   - リポジトリ → Settings → いちばん下の「Danger Zone」→ Change visibility → Change to public
   - ※無料プランでは、Publicにしないとサイトを公開できません
2. **GitHub Pages をONにする**
   - リポジトリ → Settings → 左メニューの「Pages」→ Build and deployment の Source を「**GitHub Actions**」にする
3. **mainに一度マージする**（上の手順2と同じ）
4. 公開URLは `https://ユーザー名.github.io/リポジトリ名/` になる

> 💡 **サイトはいくつでも作れます。** GitHubは「1リポジトリ＝1サイト」。
> 新しい棚（リポジトリ）を作れば、その数だけサイトを無料で公開できます。

## 5. 困ったときは

| 症状 | 対処 |
|---|---|
| Actionsに ❌ 赤いバツが出た | その行を押すとエラー内容が見られます。わからなければ、**その画面のスクリーンショットをClaudeに送る**のがいちばん早いです。 |
| 黄色い帯（Compare & pull request）が出ない | Pull requests タブ → New pull request から手動で作れます（手順2参照）。 |
| マージしたのにサイトが変わらない | 2〜3分待つ → ページを再読み込み。それでもダメならActionsで緑✅か確認。 |
| まちがえてマージしてしまった | 元に戻せます。あわてずClaudeに「さっきのマージを取り消したい」と伝えてください。 |
| Settingsが見つからない（スマホ） | 上部タブの「More ▾」の中にあります。なければブラウザの「デスクトップ用サイトを表示」をON。 |

### 大原則

- **本棚（main）を直接さわらない。** 変更はいつも「下書き → マージ」の順で。
- **わからなくなったら、押す前にスクリーンショットを撮ってClaudeに相談。** 壊れることはほぼありませんが、聞くのがいちばん安全で早いです。

## 6. ふだんの更新の頼み方（例文）

Claudeへはふつうの日本語で頼めば大丈夫です。例：

- 「料金を〇〇円に変えて、公開まで進めて」
- 「ブログに『スマホの文字を大きくする方法』の記事を追加して」
- 「電話番号が決まりました。000-1234-5678に全部差し替えて」

Claudeが変更を作ってプッシュしたら、あなたは**手順2のマージをするだけ**です。
