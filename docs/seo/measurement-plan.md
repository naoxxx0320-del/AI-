# 計測計画（2026-11-18）

## 1. アクセス解析（GA4）の有効化

計測の仕組みは実装済み。**測定IDが空のあいだは何も読み込まず、何も送らない。**

1. Google アナリティクスで GA4 プロパティを作り、ウェブストリームの「測定ID」（`G-` で始まる）を控える
2. `public/assets/config.js` の `GA_MEASUREMENT_ID: ""` に測定IDを入れる
3. `contact.html` の「個人情報の取り扱い」に、アクセス解析を使う旨を書き足す
4. main に反映 → 公開後、GA4 の「リアルタイム」でイベントが届くことを確かめる

架空のIDを本番に置かないこと。

## 2. イベントの定義

| イベント | 発火する条件 | 送る値 | 意味しないこと |
|---|---|---|---|
| `course_detail_click` | サイト内の `/course/*.html` へのリンクをクリック | `course_id`（例: taiken）、`link_location`（price, hero, footer など） | 申し込み |
| `contact_start` | 申込フォームに最初に入力した時（1表示につき1回） | なし | 送信 |
| `contact_success` | **送信先（Web3Forms）が成功を返した時だけ** | `method: form` | 完了ページの表示（直接開いても数えない） |
| `phone_click` | `tel:` リンクのクリック | `link_location` | 通話の成立・予約 |
| `line_click` | LINE へのリンクのクリック | `link_location` | 友だち追加・メッセージ送信 |

氏名・電話番号・メールアドレス・自由記述・電話番号を含むリンク先は送らない。試験の記録は `verification.md` の A28・A29。

主要な成果は `contact_success`。電話クリックは「かけようとした操作」であり、予約数と同じに扱わない。

## 3. Search Console での比較方法

接続できていないため、運営者の操作で取り出す。

1. Search Console →「検索パフォーマンス」→ 検索タイプ「ウェブ」、国「日本」
2. 期間「比較」→「過去28日間と前の期間」。データが少なければ「過去3か月」
3. 「デバイス」タブでモバイルとパソコンを比べる。同じ検索語・同じページに絞ってから比べる（サイト全体の平均順位で判断しない）
4. 「エクスポート」→ Google スプレッドシートまたは CSV

### 指名検索を除く（教室名・講師名を含まない検索）

「検索キーワード」→「＋新規」→「カスタム（正規表現）」→「一致しないキーワード」に次を入れる。

```
すみだ\s*ai|すみだ\s*ＡＩ|sumida[- ]?ai|竹内\s*直政|ai\s*プロジェクトチーム
```

匿名化された検索語は集計に出ないため、この合計を全体の完全な内訳とはしない。

### 主要URLの URL 検査

`/`・`/sumida.html`・`/courses.html`・`/course/taiken.html`・`/course/jitaku.html`・`/teacher.html` について、
「URL検査」で「Google が選択した正規URL」と「インデックス登録」を記録する。

## 4. 公開後の確認予定

| 時期 | すること |
|---|---|
| 公開当日 | 主要URL・内部リンク・canonical・robots・サイトマップを本番で確認（`verification.md` に記録済み） |
| 1〜2週間後 | 主要URLの URL 検査。問題のあるURLだけ登録をリクエスト |
| 28日後 | 公開前の同じ長さの期間と、指名検索を除く表示回数・クリック、`contact_success` を比べる |
| 60〜90日後 | 表示はあるのに意図が合っていないページ、講座への移動が少ない記事を見直す |

これは確認の時期であり、順位が上がる約束ではない。サイトマップの再送信や登録リクエストの繰り返しは上位表示の施策にはならない。
